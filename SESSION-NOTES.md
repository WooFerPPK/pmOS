## Where the runway points next

With the `2955d62` socket-cleanup-on-proc_exit slice landed, the documented tech-debt from `cf20126` is gone: `Kernel::proc_exit` releases fd-table-owned resources the instant a process exits, so display-server's `/run/display` binding no longer survives as an orphan listener. The WASI `proc_exit` shim in `web/src/user-wasm-runtime.ts` now dispatches the PROC_EXIT opcode to the kernel before throwing `UserProcessExited` — load-bearing complement; without it the kernel would still not see any userland exit. The four-pid default-boot substrate is unchanged under Playwright (init + hello-std + display-server + display-client-demo concurrent Workers, round-trip completes as before). Under sequential vitest `runAllSpawns`, display-client-demo's exit code is now 10 (display_connect ECONNREFUSED poll exhaustion) rather than 11 (fd_write EINVAL retry exhaustion against the orphan listener). Long-running init supervision of children stays blocked on `proc_wait` T075; `ipc_accept` still returns `-EAGAIN` on an empty backlog (not blocking). Pick one for the next session:

- **Stretch the WASI surface further** (lowest-architectural-risk family; pick any one). The CLOCK_TIME_GET slice (`dcab1e5`) proves the three-layer shape (Platform method + kernel-side handler + TS-side shim + shared constants + tests at every layer). Natural next candidates from the same shape: (a) `clock_res_get` — the precision-query sibling to `clock_time_get` that the contract already says supports monotonic + realtime + process_cputime (cputime returns ENOTSUP by the same split the time handler uses). Tightest session-sized companion to the CLOCK_TIME_GET slice. (b) `fd_filestat_get` / `path_filestat_get` — unblocks `fs::metadata` + `File::metadata` for std binaries; wider than the clock slice because it adds a full `filestat_t` wire layout. (c) `poll_oneoff` — the complex one; unblocks `std::net`-like async patterns + `mio`-based userland, but is genuinely larger (subscription decoding + clock + fd-readable/writable + the "at least one ready" contract). `clock_res_get` is the tightest session-sized candidate today.
- **Pending-Connecting-client cleanup on listener drop** (stretch refinement to the slice just landed, small). Today's `proc_exit` cleanup handles the common case (release the exiter's own bindings + socket fds), but a specific edge case is not yet covered: when a listener socket is dropped while pending Connecting clients are queued on its backlog, those clients stay in `Connecting` state with `peer = None`. A subsequent `fd_write` on a pending-Connecting client returns `InvalidState → EINVAL` rather than something semantically cleaner like EPIPE or ECONNREFUSED. Not exercised by any current test (the sequential vitest flow never has a pending client when the server exits; the concurrent Playwright flow always accepts before exit), but architecturally nicer to handle. Would add a backlog-drain step to `IpcTable::close_socket` + possibly a new errno-mapping branch. Session-sized but narrow; only pick up if the slice after wants to polish the IPC state machine rather than expand the WASI surface.
- **Long-running accept loop (display-server serves multiple clients)** (larger architectural slice, still blocked on `proc_wait` T075). Today's display-server accepts ONE client then exits. A real display-server serves N clients over time.
